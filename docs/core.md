# Устройство эмулятора RISC-V

Этот документ описывает фактическую реализацию ядра `riscv-emu-core`: модель CPU, декодирование и исполнение RV32IM, память, ELF-загрузчик, системные вызовы, интеграцию с Doom и WebAssembly. Документ относится к текущей MVP-версии проекта.

## 1. Назначение и границы проекта

Эмулятор исполняет 32-битный машинный код RISC-V в браузере. Основная целевая программа — порт Doom Generic, собранный для `RV32IM/ILP32`.

Поддерживается:

- базовый набор команд RV32I;
- целочисленное расширение M;
- 32 регистра общего назначения и программный счётчик;
- 8 MiB гостевой памяти;
- little-endian чтение и запись;
- ELF32 RISC-V с сегментами `PT_LOAD`;
- два соглашения о системных вызовах: Doom/rvcore и минимальное стандартное RISC-V;
- UART, таймер, клавиатура и framebuffer;
- загрузка WAD в виртуальный файловый дескриптор;
- выполнение ядра в WebAssembly.

Не поддерживаются:

- привилегированные режимы RISC-V;
- MMU и виртуальная память;
- прерывания и исключения уровня машины;
- расширения A, C, F, D и V;
- полноценные CSR;
- операционная система Linux;
- звук и постоянная файловая система.

## 2. Структура исходного кода

| Файл | Назначение |
|---|---|
| `src/lib.rs` | Публичный API крейта и реэкспорт основных типов |
| `src/cpu.rs` | Состояние процессора и цикл fetch-decode-execute |
| `src/decode.rs` | Извлечение полей и immediate из инструкции |
| `src/execute.rs` | Семантика команд RV32IM |
| `src/memory.rs` | DRAM, MMIO, framebuffer, клавиатура и ловушки памяти |
| `src/elf.rs` | Проверка и загрузка ELF32 |
| `src/syscall.rs` | Обработка `ECALL` и виртуальный доступ к WAD |

Крейт `wasm` не входит в ядро, но предоставляет браузеру безопасную обёртку над `Cpu`.

## 3. Модель CPU

Главный тип — `Cpu`:

```rust
pub struct Cpu {
    pub regs: [u32; 32],
    pub pc: u32,
    pub mem: Memory,
    pub csr: Csr,
    pub heap: u32,
    pub halted: bool,
    pub wad: Vec<u8>,
    pub wad_position: usize,
}
```

### Регистры

`regs[0..32]` соответствуют архитектурным регистрам `x0..x31`. Запись в `x0` игнорируется функцией `wr`, а после каждой инструкции `x0` дополнительно обнуляется. Аргументы системных вызовов используют стандартные ABI-имена:

- `x2` — `sp`, указатель стека;
- `x10..x12` — `a0..a2`, аргументы и возвращаемые значения;
- `x17` — `a7`, номер системного вызова.

### Счётчики

`Csr` пока содержит только программные счётчики:

- `cycle` — количество успешно исполненных инструкций;
- `instret` — количество завершённых инструкций.

Они не доступны гостевой программе через CSR-инструкции и служат основой для будущей диагностики.

### Один шаг исполнения

`Cpu::step()` выполняет следующий алгоритм:

1. Проверяет, не остановлен ли CPU.
2. Проверяет выравнивание `pc` по четырём байтам.
3. Читает 32-битную инструкцию из памяти.
4. Вызывает `decode()`.
5. Передаёт результат в `execute()`.
6. Восстанавливает `x0 = 0`.
7. Увеличивает `cycle` и `instret`.

Сжатые 16-битные инструкции RVC не поддерживаются, поэтому `pc` всегда должен быть кратен четырём.

`Cpu::run(n)` повторяет `step()` ровно `n` раз либо прекращает выполнение при первой ловушке.

## 4. Декодирование инструкций

`decode()` извлекает без изменения смысла инструкции:

- `opcode`;
- `rd`, `rs1`, `rs2`;
- `funct3`, `funct7`;
- знаково расширенный `imm`;
- исходное слово `raw` для диагностики.

Immediate собирается отдельно для форматов I, S, B, U и J. Знаковое расширение выполняется функцией `sext`. Декодер не проверяет допустимость комбинации полей: эта проверка выполняется в `execute()`.

## 5. Поддерживаемые команды RV32IM

### RV32I

| Группа | Команды |
|---|---|
| Upper immediate | `LUI`, `AUIPC` |
| Переходы | `JAL`, `JALR` |
| Ветвления | `BEQ`, `BNE`, `BLT`, `BGE`, `BLTU`, `BGEU` |
| Загрузки | `LB`, `LH`, `LW`, `LBU`, `LHU` |
| Сохранения | `SB`, `SH`, `SW` |
| Immediate ALU | `ADDI`, `SLTI`, `SLTIU`, `XORI`, `ORI`, `ANDI`, `SLLI`, `SRLI`, `SRAI` |
| Register ALU | `ADD`, `SUB`, `SLL`, `SLT`, `SLTU`, `XOR`, `SRL`, `SRA`, `OR`, `AND` |
| Синхронизация | `FENCE` трактуется как NOP |
| System | `ECALL`, `EBREAK` |

### Расширение M

Поддерживаются `MUL`, `MULH`, `MULHSU`, `MULHU`, `DIV`, `DIVU`, `REM`, `REMU`.

Граничные случаи деления реализованы по спецификации RISC-V:

- деление на ноль возвращает максимальное беззнаковое значение для частного;
- остаток при делении на ноль равен делимому;
- `INT_MIN / -1` возвращает `INT_MIN`;
- остаток для `INT_MIN % -1` равен нулю.

Неизвестный opcode или недопустимая комбинация `funct3/funct7` создаёт `Trap::IllegalInstruction(raw)`.

## 6. Память

`Memory` владеет следующими областями:

```rust
pub struct Memory {
    pub dram: Vec<u8>,
    pub framebuffer: Vec<u8>,
    pub uart_buffer: String,
    // очередь клавиш и значение таймера
}
```

### Карта памяти

| Область | Адрес/размер | Назначение |
|---|---:|---|
| DRAM, low alias | `0x0000_0000..0x007f_ffff` | Совместимость с rvcore Doom ELF |
| DRAM, high alias | `0x8000_0000..0x807f_ffff` | Стандартная bare-metal карта |
| UART | `0x1000_0000` | Вывод одного байта |
| Keyboard | `0x1000_0004` | Получение следующего кода клавиши |
| Timer | `0x1000_0008` | Миллисекунды, переданные хостом |
| MMIO framebuffer | `0x8020_0000` | Альтернативная запись изображения |

Low и high диапазоны адресуют один и тот же массив DRAM. Это позволяет исполнять как программы, слинкованные от нулевого адреса, так и обычные bare-metal программы от `0x8000_0000`.

### Endianness и выравнивание

Память работает в little-endian режиме. Методы `read_u16`, `read_u32`, `write_u16` и `write_u32` поддерживают невыравненные адреса. Это требуется библиотекой newlib и портом Doom.

Выбор сделан намеренно: архитектура может аппаратно ловить misaligned-доступы, но эталонный rvcore программно обслуживает их. Выравнивание выборки инструкции проверяется отдельно в `Cpu::step()`.

### Ловушки памяти

`Trap` описывает ошибки выполнения:

| Вариант | Значение |
|---|---|
| `AccessFault(addr)` | Адрес вышел за доступную память или heap пересёк стек |
| `Misaligned(addr)` | Невыровненный `pc` |
| `IllegalInstruction(raw)` | Неподдержанная инструкция |
| `Breakpoint` | Выполнен `EBREAK` |
| `Ecall(number)` | Неизвестный системный вызов |
| `Halted(code)` | Гостевая программа завершилась |

## 7. Клавиатура

Поддерживаются одновременно два интерфейса ввода.

### MMIO

`push_key(code)` добавляет код в `VecDeque`. Чтение `KEYBOARD_ADDR` удаляет и возвращает первый код, а при пустой очереди возвращает ноль.

### Очередь rvcore

Doom использует кольцевой буфер из 16 событий в конце DRAM. Одно событие — `u16`:

- младший байт — код клавиши Doom Generic;
- старший байт — признак нажатия (`1`).

`push_key()` записывает событие в этот буфер и передвигает write index. Read index обновляет гостевая программа.

## 8. Framebuffer

Публичный framebuffer имеет размер `640 × 400 × 4` байт. Doom рисует в зарезервированную область в конце DRAM в формате `XRGB8888`. Системный вызов Doom `8` копирует эту область в `Memory::framebuffer`.

В браузере данные преобразуются из little-endian XRGB/BGRA-представления в RGBA:

1. красный и синий каналы меняются местами;
2. alpha устанавливается в `255`;
3. результат передаётся в `ImageData` и `putImageData`.

Без установки alpha кадр был бы полностью прозрачным.

## 9. UART и таймер

Запись байта в `UART_ADDR` добавляет символ в `uart_buffer`. Хост получает и одновременно очищает накопленный текст через `take_uart()`/`uart_output()`.

Таймер не читает системное время самостоятельно. JavaScript вызывает `set_ticks_ms()` перед очередной порцией инструкций. Это делает ядро детерминированным и не привязывает его к `std::time`.

## 10. ELF-загрузчик

Загрузчик принимает ELF при выполнении условий:

- magic равен `0x7f, E, L, F`;
- класс — ELF32;
- порядок байтов — little-endian;
- `e_machine == 243`, то есть RISC-V.

Для каждого program header типа `PT_LOAD`:

1. `p_filesz` байт копируются из файла по `p_vaddr`;
2. разница `p_memsz - p_filesz` заполняется нулями для BSS;
3. вычисляется максимальный конец загруженного образа.

Загрузчик возвращает `e_entry` и конец образа. Для low-address ELF:

- `pc` устанавливается в `e_entry`;
- heap начинается с выровненного вверх конца образа;
- `sp` ставится перед зарезервированной видеопамятью.

Автоматический расчёт heap важен: фиксированный адрес оставлял лишний зазор и приводил к ложному столкновению heap со стеком во время запуска Doom.

## 11. Системные вызовы и Host

Инструкция `ECALL` берёт номер из `a7` (`x17`).

Ядро объявляет trait `Host`, через который платформа может обработать `ECALL`. Сам Doom/rvcore ABI и виртуальный WAD реализованы в крейте `wasm`, а не в `core`.

### Doom/rvcore ABI в WASM host

| № | Операция | Реализация |
|---:|---|---|
| 0 | `_sbrk` | Перемещает heap и проверяет его относительно `sp` |
| 1 | `_open` | Открывает виртуальный WAD, возвращает fd 3 |
| 2 | `_read` | Копирует данные WAD в гостевую память |
| 3 | `_write` | Перенаправляет байты в UART |
| 4 | `_lseek` | Меняет позицию в WAD для `SEEK_SET/CUR/END` |
| 5 | `_close` | Успешная заглушка |
| 6 | `_gettimeofday` | Возвращает секунды и микросекунды через `a0..a2` |
| 7 | `_usleep` | Неблокирующая заглушка |
| 8 | `_render_frame` | Копирует Doom VRAM в публичный framebuffer |
| 9–12 | Файловые изменения | Возвращают ошибку |
| 15 | `_exit` | Останавливает CPU |

Файловая модель специально минимальна: любой `open` относится к одному заранее загруженному WAD. Этого достаточно для текущего Doom Generic, но недостаточно для произвольных приложений.

### Дополнительный ABI

Также реализованы номера 57, 62, 63, 64, 80, 93, 169 и 214 для простых RISC-V/newlib-подобных программ: `close`, `lseek`, `read`, `write`, `fstat`, `exit`, `gettimeofday`, `sbrk`.

## 12. WAD

`WasmRiscv::load_wad(data)` сохраняет WAD в `DoomHost` внутри крейта `wasm`, отдельно от CPU и гостевой DRAM. Это важно, поскольку Freedoom WAD имеет размер около 27 MiB, а гостевая DRAM — 8 MiB. Универсальное ядро не знает о формате WAD.

Гостевая программа видит WAD как обычный seekable-файл. В проекте используется Freedoom Phase 2: порт сначала пытается открыть Doom II IWAD и ожидает Doom II lumps, включая `D_DM2TTL`.

## 13. WebAssembly API

`wasm/src/lib.rs` экспортирует класс `WasmRiscv`:

| Метод | Назначение |
|---|---|
| `new()` | Создать CPU и память |
| `load_elf(data)` | Загрузить ELF32 и установить `pc` |
| `load_binary(address, data)` | Загрузить flat binary |
| `load_wad(data)` | Подключить виртуальный WAD |
| `run(count)` | Исполнить указанное число инструкций |
| `pc()` | Прочитать программный счётчик |
| `reg(index)` | Прочитать регистр |
| `framebuffer_ptr()` | Получить адрес framebuffer в WASM memory |
| `framebuffer_size()` | Получить размер framebuffer |
| `uart_output()` | Забрать накопленный текст UART |
| `push_key(code)` | Передать клавишу |
| `set_ticks_ms(value)` | Обновить таймер |
| `halted()` | Проверить завершение программы |

`Trap::Halted` считается штатным завершением и не превращается в JavaScript exception. Остальные ловушки возвращаются как `JsValue` со строкой диагностики.

## 14. Браузерный цикл

Frontend выполняет следующую последовательность:

1. Инициализирует WASM-модуль.
2. Параллельно загружает `doom.elf` и `doom1.wad`.
3. Передаёт оба файла в эмулятор.
4. На каждом `requestAnimationFrame` обновляет таймер.
5. Исполняет пакет инструкций.
6. Создаёт актуальный view на WASM memory.
7. Конвертирует пиксели XRGB в RGBA.
8. Рисует кадр на canvas.
9. Выводит UART в консоль браузера.

View создаётся заново после исполнения, потому что рост WASM memory может инвалидировать старый `ArrayBuffer`.

## 16. Сборка WASM

```sh
cd wasm
wasm-pack build --target web --release --out-dir ../web/pkg
```

Release-профиль workspace включает `opt-level = 3`, fat LTO, один codegen unit и `panic = abort`. `wasm-pack` дополнительно запускает `wasm-opt`.

## 17. Известные ограничения и направления развития

1. Выполнение — простой интерпретатор с одним большим `match`; нет block cache или JIT.
2. Framebuffer полностью копируется и конвертируется каждый кадр.
3. Клавиатура сейчас передаёт события нажатия; полноценные key-up события можно добавить отдельно.
4. Виртуальная файловая система содержит только один WAD.
5. CSR-инструкции, таймерные прерывания и privileged ISA отсутствуют.
6. Нет официального прогона полного набора `riscv-tests`.
7. Нет аудиоустройства.
8. Ловушки представлены Rust-ошибками, а не архитектурными RISC-V trap handlers.

Для дальнейшей оптимизации наиболее полезны выполнение до события кадра вместо фиксированного количества инструкций, кэширование декодированных basic blocks и перенос преобразования XRGB→RGBA в ядро или WebGL shader.
